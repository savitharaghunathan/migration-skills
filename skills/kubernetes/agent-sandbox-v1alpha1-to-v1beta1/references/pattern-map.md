# Pattern Map — Agent Sandbox v1alpha1 to v1beta1

| description | category | before | after | notes | source_section |
|---|---|---|---|---|---|
| Back up all Agent Sandbox resources before migration | addition | N/A | `kubectl get sandboxes,sandboxclaims,sandboxtemplates,sandboxwarmpools -A -o yaml > agent-sandbox-backup-$(date -u +%Y%%m%%dT%H%%M%%SZ).yaml` | Keep the file somewhere durable; needed for rollback or inspecting original v1alpha1 shape | Before you start: back up your data |
| Run bootstrap phase to pre-create shadow pools before upgrading CRDs | structural | N/A | `bash dev/tools/migrate.sh --phase=bootstrap` | Must run BEFORE v1beta1 CRDs/controller are applied; operates on v1alpha1 API; creates shadow-pool-<template> per (namespace, template) for cold-start claims | Two phases |
| Run migrate phase to force-rewrite resources to v1beta1 storage | structural | N/A | `bash dev/tools/migrate.sh --phase=migrate` | Must run AFTER v1beta1 CRDs and conversion webhook are live; patches every resource with annotation to force API server read-through conversion webhook; for large clusters scope per namespace with `--namespace=<ns>` | Two phases |
| Both migration phases are idempotent | behavioral | N/A | N/A | Safe to re-run both bootstrap and migrate phases | Two phases |
| Shadow pools are created with migration annotations | addition | N/A | `agents.x-k8s.io/migration-shadow: "true"` and `agents.x-k8s.io/migration-source-template: <template-name>` | Do NOT delete shadow pools while any v1beta1 SandboxClaim still references them via warmPoolRef | After migration completes |
| Re-point warm-started claims to preferred pools after migration | structural | Claims reference shadow-pool-<template> | `kubectl patch sandboxclaim <name> -n <ns> --type=merge -p '{"spec":{"warmPoolRef":{"name":"my-preferred-pool"}}}'` | warmPoolRef.name is editable on v1beta1 claims; once all claims are re-pointed, shadow pools can be cleaned up | After migration completes |
| Helm does not upgrade CRDs on helm upgrade | behavioral | N/A | `kubectl apply --server-side --force-conflicts -f path/to/chart/crds/` | CRDs must be applied manually before running helm upgrade | Flow B — Helm-managed |
| Wait for conversion webhook to be responsive before running migrate phase | addition | N/A | `until kubectl get sandboxwarmpools.extensions.agents.x-k8s.io -A >/dev/null 2>&1; do echo "Waiting..."; sleep 2; done` | Webhook may take a few seconds after pod starts; do not run migrate phase until webhook responds | Migration flows |
| Verify migration by checking storage-migrated-at annotation | addition | N/A | `kubectl get sandboxes,sandboxclaims,sandboxtemplates,sandboxwarmpools -A -o json \| jq -r '.items[] \| "\(.kind) \(.metadata.namespace)/\(.metadata.name) -> \(.metadata.annotations["agents.x-k8s.io/storage-migrated-at"] // "<missing>")"'` | Every resource should have this annotation after successful migration | Verifying the migration worked |
| Verify CRD storedVersions shows only v1beta1 | addition | `status.storedVersions: ["v1alpha1","v1beta1"]` | `status.storedVersions: ["v1beta1"]` | If both versions still listed after rewrite, prune with: `kubectl patch crd <name> --subresource=status --type=merge -p '{"status":{"storedVersions":["v1beta1"]}}'` | Verifying the migration worked |
| Dry-run both phases before actual migration | addition | N/A | `bash dev/tools/migrate.sh --phase=bootstrap --dry-run` and `bash dev/tools/migrate.sh --phase=migrate --dry-run` | Bootstrap dry-run prints "operator action required" summary for claims referencing missing pools | Dry-runs |
| Bootstrap may print OPERATOR ACTION REQUIRED for missing pools | behavioral | Claims reference specific pools that don't exist | Either create missing pools manually OR re-point claims to existing pools via kubectl patch | Operator must resolve these before or after migration | Troubleshooting |
| GKE private clusters may block webhook on port 9443 | behavioral | N/A | Create firewall rule allowing ingress from GKE master IP range to workers on TCP 9443 | Control plane VPC can't reach webhook port; causes connection refused or timeouts | Troubleshooting |
| Emergency rollback procedure reverts to v1alpha1 | removal | v1beta1 resources | Disable webhooks → scale down controller → delete resources → reset storedVersions → revert CRDs → restore from backup | Only for critical failures; see guide for 7-step procedure | Emergency Rollback Procedure |
| Per-resource recovery from backup on v1beta1 | structural | Broken/corrupt v1beta1 resource | `kubectl delete <kind> <name> -n <ns>` then re-apply from backup YAML; conversion webhook re-converts on apply | Depends on functioning conversion webhook; strip status before re-apply | Recovery from Backup |
