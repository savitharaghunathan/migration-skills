# Pattern Map — Apache HttpClient 4.x to 5.x

| description | category | before | after | notes | source_section |
|---|---|---|---|---|---|
| Timeout values now use `Timeout` class instead of raw int milliseconds | structural | `.setConnectTimeout(60000).setSocketTimeout(60000)` | `.setConnectTimeout(Timeout.ofMinutes(1)).setSocketTimeout(Timeout.ofMinutes(1))` | Import `org.apache.hc.core5.util.Timeout` | Migration steps |
| Time duration values now use `TimeValue` class instead of `long, TimeUnit` pairs | structural | `.setConnectionTimeToLive(1, TimeUnit.MINUTES)` | `.setTimeToLive(TimeValue.ofMinutes(10))` | Import `org.apache.hc.core5.util.TimeValue` | Migration steps |
| Connection manager creation uses builder pattern instead of constructor | structural | `PoolingHttpClientConnectionManager cm = new PoolingHttpClientConnectionManager(); cm.setMaxTotal(100);` | `PoolingHttpClientConnectionManager cm = PoolingHttpClientConnectionManagerBuilder.create().setMaxConnTotal(100).build();` | Use `PoolingHttpClientConnectionManagerBuilder` for all connection manager config | Migration steps |
| TLS/SSL configuration uses `ClientTlsStrategyBuilder` instead of `SSLConnectionSocketFactory` | structural | `new SSLConnectionSocketFactory(SSLContexts.createSystemDefault(), new String[]{"TLSv1.2"}, null, SSLConnectionSocketFactory.getDefaultHostnameVerifier())` | `ClientTlsStrategyBuilder.create().setSslContext(SSLContexts.createSystemDefault()).setTlsVersions(TLS.V_1_3).buildClassic()` | TLS strategy set on connection manager builder via `.setTlsSocketStrategy()` | Migration steps |
| Connect timeout and socket timeout moved from `RequestConfig` to `ConnectionConfig` | structural | `RequestConfig.custom().setConnectTimeout(60000).setSocketTimeout(60000).build()` | `ConnectionConfig.custom().setConnectTimeout(Timeout.ofMinutes(1)).setSocketTimeout(Timeout.ofMinutes(1)).build()` | Set on connection manager via `.setDefaultConnectionConfig()` | Migration recipes |
| Socket config now set on connection manager builder, not on `HttpClients.custom()` | structural | `HttpClients.custom().setDefaultSocketConfig(socketConfig)` | `PoolingHttpClientConnectionManagerBuilder.create().setDefaultSocketConfig(socketConfig)` | Then pass connection manager to `HttpClients.custom().setConnectionManager(cm)` | Migration recipes |
| HTTP response no longer has status line object; use response code directly | structural | `response.getStatusLine().getStatusCode()` | `response.getCode()` | Use `new StatusLine(response)` if status line string is needed | Migration recipes |
| Request building uses `ClassicRequestBuilder` instead of method-specific classes for entity requests | structural | `HttpPost httpPost = new HttpPost(url); httpPost.setEntity(entity);` | `ClassicHttpRequest httpPost = ClassicRequestBuilder.post(url).setEntity(HttpEntities.create(...)).build();` | Method-specific classes (HttpGet, HttpPost) still work for simple cases | Migration steps |
| Entity creation uses `HttpEntities` factory methods | structural | `new EntityTemplate(outstream -> { ... }); entity.setContentType(contentType);` | `HttpEntities.create(outstream -> { ... }, ContentType.APPLICATION_JSON)` | Content type passed to factory method, not set separately | Migration steps |
| Connection pool concurrency policy can be configured (STRICT or LAX) | addition | | `.setPoolConcurrencyPolicy(PoolConcurrencyPolicy.STRICT)` | `STRICT` for guaranteed limits; `LAX` for higher concurrency with relaxed limits | Migration steps |
| Connection pool reuse policy can be configured (LIFO or FIFO) | addition | | `.setConnPoolPolicy(PoolReusePolicy.LIFO)` | `LIFO` allows idle connections to expire; `FIFO` keeps all connections active | Migration steps |
| Zero TTL means connections are not reused (changed from unlimited in 4.x) | behavioral | `.setConnectionTimeToLive(0, TimeUnit.MILLISECONDS)` (unlimited) | `.setTimeToLive(TimeValue.NEG1_MILLISECOND)` (use negative for unlimited) | Zero TTL in 5.x = single-use connections; use negative for unlimited | Migration steps |
| Retry handler replaced by retry strategy | structural | `.setRetryHandler(new DefaultHttpRequestRetryHandler(3, true))` | `.setRetryStrategy(new DefaultHttpRequestRetryStrategy(3, TimeValue.ofSeconds(1)))` | `HttpRequestRetryStrategy` supports retry interval configuration | Migration recipes |
| Interceptor registration uses named exec interceptors | structural | `.addInterceptorLast(loggingInterceptor)` | `.addExecInterceptorFirst("logging", loggingInterceptor)` | Named exec interceptors prevent logging of compressed payload | Migration recipes |
| Co-location: HttpClient 4.x and 5.x can coexist on the same classpath | addition | | | Different Maven coordinates and Java package namespaces allow gradual migration | Migration steps |
| Async client requires explicit start before executing requests | structural | (classic client is ready immediately after creation) | `client.start();` | `CloseableHttpAsyncClient` must be started; classic client does not | Migration to async APIs |
| Async client uses `Future` and `FutureCallback` for request execution | structural | `CloseableHttpResponse response = client.execute(request);` | `Future<?> future = client.execute(request, callback); future.get();` | Async execution returns `Future`; use `FutureCallback` for event handling | Migration to async APIs |
| Async connection manager uses `PoolingAsyncClientConnectionManager` | structural | `PoolingHttpClientConnectionManager cm = ...` | `PoolingAsyncClientConnectionManager cm = PoolingAsyncClientConnectionManagerBuilder.create()...build();` | Different builder; supports `TlsConfig` instead of `SocketConfig` | Migration to async APIs |
| Async client uses `SimpleHttpRequest`/`SimpleHttpResponse` for simple message handlers | structural | `HttpPost post = new HttpPost(url); post.setEntity(entity);` | `SimpleHttpRequest post = SimpleRequestBuilder.post(url).setBody(body, contentType).build();` | Simple handlers buffer content in memory; use for small messages only | Migration to async APIs |
| Async client graceful shutdown | structural | `client.close();` | `client.close(CloseMode.GRACEFUL);` | `CloseMode.GRACEFUL` waits for in-flight requests to complete | Migration to async APIs |
| HTTP/2 only client uses dedicated builder without connection manager | structural | `HttpClients.custom().setConnectionManager(cm).build()` | `HttpAsyncClients.customHttp2().setTlsStrategy(...).build()` | HTTP/2 client maintains internal connection map; no external connection manager | Migration to HTTP/2 APIs |
| HTTP/2 client does not support HTTP proxy | behavioral | (proxy configuration available in classic and HTTP/1.1 async client) | N/A | HTTP/2 optimized clients presently do not support proxy | Migration to HTTP/2 APIs |
| HTTP version policy selection for async clients | addition | | `.setDefaultTlsConfig(TlsConfig.custom().setVersionPolicy(HttpVersionPolicy.NEGOTIATE).build())` | Policies: `NEGOTIATE` (HTTP/2 via ALPN), `FORCE_HTTP_1`, `FORCE_HTTP_2` | Migration to async APIs |
| `URIBuilder.normalizeSyntax()` deprecated since 5.3, renamed to `optimize()` | behavioral | `new URIBuilder(uri).normalizeSyntax().build()` | `new URIBuilder(uri).optimize().build()` | 5.x `optimize()` performs more thorough RFC 3986 normalization than 4.x `URIUtils.normalizeSyntax()` | Migration steps |
