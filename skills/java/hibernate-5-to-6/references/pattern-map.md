# Pattern Map — Hibernate 5 to 6

| description | category | before | after | notes | source_section |
|---|---|---|---|---|---|
| Java 11 is the minimum baseline (was Java 8) | addition | | JDK 11+ required at compile and runtime | JDK 17 recommended for Hibernate 6.2+ | Java 11 |
| Jakarta Persistence XSD namespaces must be updated in persistence.xml and orm.xml | structural | `xmlns="http://xmlns.jcp.org/xml/ns/persistence" version="2.2"` | `xmlns="https://jakarta.ee/xml/ns/persistence" version="3.0"` | Eclipse Transformer tool available for automated conversion | Jakarta Persistence |
| ResultSet reading changed from name-based to position-based for performance | behavioral | | | Internal change; affects custom types that extend Hibernate SPI and read from ResultSet by column name | Reading from JDBC |
| Generated SQL no longer uses column aliases; column references are unique-d | behavioral | `SELECT col1 AS col0_0_, col2 AS col1_0_ FROM ...` | `SELECT t1.col1, t1.col2 FROM ...` | May affect native SQL queries or logging-based assertions | Generated SQL |
| Identifier types no longer require Serializable | structural | `public class MyEntity { Serializable getId() {...} }` | `public class MyEntity { Object getId() {...} }` | Affects APIs that accepted Serializable identifiers | Identifier as Object |
| Per-entity ID sequences instead of single shared hibernate_sequence | behavioral | `@GeneratedValue(strategy=GenerationType.AUTO)` uses `hibernate_sequence` | `@GeneratedValue(strategy=GenerationType.AUTO)` uses `<entity_name>_seq` | Run hbm2ddl to generate new sequences; or set `hibernate.id.db_structure_naming_strategy=single` for backward compat | Implicit Identifier Sequence and Table Name |
| Implicit sequence allocation size defaults to JPA standard of 50 | behavioral | `@GeneratedValue` with implicit allocationSize (was 1 or DB default) | `@GeneratedValue` with allocationSize=50 (JPA default) | Must reset sequences in import.sql: `alter sequence person_seq restart with <max_id + 1 + 50>` | Defaults for implicit sequence generators |
| @TypeDef/@TypeDefs removed — use direct type annotations | structural | `@TypeDef(name="json", typeClass=JsonType.class)` on package-info.java, then `@Type(type="json")` on fields | `@Type(JsonType.class)` directly on fields, or `@JdbcTypeCode`/`@JavaType` annotations | No more string-based type references | Type system |
| Boolean types (yes_no, true_false, numeric_boolean) use AttributeConverter | structural | `@Type(type="yes_no") boolean active;` | `@Convert(converter=YesNoConverter.class) boolean active;` | Can register as auto-apply converter for consistency | Type system — Boolean converters |
| Different embeddable mappings for same Java class no longer supported | removal | Two `@Embedded` fields of same class with different `@AttributeOverrides` mapping different columns | Each unique mapping combination needs its own Java class | Create separate embeddable classes for different mappings | Type system — Embeddables |
| CompositeUserType reworked to use embeddable projection class | structural | `String[] propertyNames() {...} Type[] propertyTypes() {...}` | `Class<?> embeddable() { return MonetaryAmountEmbeddable.class; }` with property index by alpha-sorted attribute names | Properties accessed by 0-based index in alphabetical order of attribute names | Type system — CompositeUserType changes |
| @Columns annotation removed for CompositeUserType | removal | `@Columns(columns={@Column(name="CURRENCY"), @Column(name="AMOUNT")})` | `@AttributeOverride(name="currency", column=@Column(name="CURRENCY"))` | Use @AttributeOverride instead | Type system — CompositeUserType changes |
| BIGINT/count() SQL results map to Long instead of BigInteger | behavioral | `BigInteger count = (BigInteger) query.getSingleResult();` | `Long count = (Long) query.getSingleResult();` | Affects native queries returning count() or BIGINT columns | Type system — SQL BIGINT mapping |
| Duration maps to INTERVAL_SECOND instead of BIGINT | behavioral | `Duration` stored as `BIGINT` (nanoseconds) | `Duration` stored as `interval second` or `numeric(21)` | Schema validation errors; set `hibernate.type.preferred_duration_jdbc_type=BIGINT` for backward compat | Duration mapping changes |
| UUID maps to native SQL UUID type instead of binary(16) | behavioral | `UUID` stored as `binary(16)` | `UUID` stored as `uuid` (or `binary(16)` fallback) | Schema validation errors on DBs with native UUID; set `hibernate.type.preferred_uuid_jdbc_type=BINARY` for backward compat | UUID mapping changes |
| Instant maps to TIMESTAMP_UTC instead of TIMESTAMP | behavioral | `Instant` stored as `timestamp` | `Instant` stored as `timestamp with time zone` (or `timestamp` fallback) | Schema validation errors; set `hibernate.type.preferred_instant_jdbc_type=TIMESTAMP` for backward compat | Instant mapping changes |
| HQL/JPQL queries with implicit joins return entity instead of Object[] | behavioral | `List<Object[]> r = session.createQuery("from Person p join p.address").list();` | `List<Person> r = session.createQuery("from Person p join p.address").list();` | Only queries without explicit select clause affected; add `select p, a` to get Object[] | Query — SQM — Result rows |
| HQL pass-through tokens no longer allowed — use sql() function | structural | `select substring(e.desc, 21, 11, octets) from AnEntity e` | `select substring(e.desc, 21, 11, sql('octets')) from AnEntity e` | Unresolvable identifiers in functions were passed as-is; now requires explicit sql() wrapper | Query — SQM — Pass-through tokens |
| FROM keyword disallowed in HQL UPDATE statements | removal | `update from MyEntity e set e.attr = null` | `update MyEntity e set e.attr = null` | Remove the `from` keyword | Query — SQM — FROM token |
| DISTINCT no longer needed to filter duplicates from join-fetched collections | behavioral | `select distinct p from Parent p join fetch p.children` | `select p from Parent p join fetch p.children` | Hibernate always filters duplicates; DISTINCT is now always passed to SQL; HINT_PASS_DISTINCT_THROUGH removed | Query — DISTINCT |
| Association comparisons with FK values no longer supported | removal | `where alias.association = 1` or `where alias.association = :param` (param bound to Integer) | `where alias.association.id = 1` or `where alias.association = :param` (param bound to entity reference) | De-reference by FK attribute (`alias.association.id = 1`) or bind entity reference | Query — Association Comparisons |
| Collection pseudo-attributes replaced with function syntax | structural | `select p.children.size from Parent p` | `select size(p.children) from Parent p` | size→size(), elements→value(), indices/index→index()/key(), maxindex→maxindex(), etc. | Query — Collection pseudo-attributes |
| Ordinal HQL parameters must be 1-based (0-based no longer supported) | behavioral | `query.setParameter(0, value);` with `?0` in HQL | `query.setParameter(1, value);` with `?1` in HQL | 0-based binding silently worked before; now throws | Query — Ordinal Parameters binding |
| ProcedureCall parameters: unset IN parameters trigger DB defaults instead of null | behavioral | Unset parameters received null | Unset parameters trigger database procedure default values | Explicitly call setParameter(null) to send null | Query — ProcedureCall Parameters |
| Query result cache stores full entity data (not just IDs) | behavioral | Query cache stored entity IDs → N+1 selects for fetched associations | Query cache stores complete entity state → single cache hit, no N+1 | May increase cache memory usage | Query result cache |
| Stream from query no longer auto-closes — must call Stream.close() explicitly | behavioral | `query.stream()` auto-managed resources | `try (Stream<T> s = query.stream()) { ... }` | Aligns with JDK Stream contract requiring explicit close for resource-backed streams | Stream |
| Fetch circularity uses width-first instead of depth-first approach | behavioral | Self-referencing eager associations fetched depth-first (fewer joins, extra selects) | Width-first fetching (more joins, fewer selects) | May generate significantly more joins with multiple eager self-references; use `fetch = LAZY` | Fetch circularity determination |
| Association laziness now properly respected with fetch="join" | behavioral | `@ManyToOne(fetch=LAZY) @Fetch(FetchMode.JOIN)` treated as eager for Session.get()/EntityManager.find() | `@ManyToOne(fetch=LAZY) @Fetch(FetchMode.JOIN)` truly lazy for all load paths | Set `fetch=EAGER` if eager loading is desired | Association laziness now respected |
| hbm.xml `<return-join/>` now causes fetch instead of adding selection item | behavioral | `<return-join alias="emp" property="org.employments">` returns `[Organization, Employee]` tuples | Returns `Organization` with initialized `employments` collection | | hbm.xml return-join behavior change |
| hbm.xml multiple `<column/>` for basic properties removed | removal | `<property name="salary"><column name="CURRENCY"/><column name="AMOUNT"/></property>` | `<component name="salary" class="CompositeUserType"><property name="value" column="AMOUNT"/>...</component>` | Use `<component>` with CompositeUserType class | Removals — hbm.xml multiple column |
| hbm.xml mapping format deprecated — will be removed after 6.x | behavioral | `<hibernate-mapping>` XML files | Migrate to annotations or orm.xml mapping files | Plan migration to annotation-based or JPA orm.xml mappings | Deprecation of hbm.xml mappings |
| JMX integration removed | removal | Hibernate JMX MBean registration | N/A | No replacement; use external monitoring tools | Removals — JMX integration |
| JACC integration removed | removal | Hibernate JACC security integration | N/A | No replacement | Removals — JACC integration |
| HQL `fetch all properties` clause removed | removal | `from Document fetch all properties` | Use entity graphs: `entityManager.createEntityGraph(Document.class)` with `jakarta.persistence.loadgraph` hint | | Removals — fetch all properties |
| 6.1: Basic arrays/collections default to SqlTypes.ARRAY instead of VARBINARY | behavioral | `double[] myArray` stored as `VARBINARY` (Java serialization) | `double[] myArray` stored as SQL `ARRAY`, `JSON`, `XML`, or `VARBINARY` depending on dialect | Schema validation errors; use `@JdbcTypeCode(SqlTypes.VARBINARY)` for backward compat; data migration required for existing rows | 6.1 — Basic array/collection mapping |
| 6.1: Enums default to SMALLINT instead of TINYINT | behavioral | Enums stored as `TINYINT` (1 byte) | Enums stored as `SMALLINT` (2 bytes) | Mostly cosmetic — many DBs already used 2+ byte type; run `alter table tbl alter column enum_col smallint` | 6.1 — Enum mapping changes |
| 6.2: OffsetTime mapping depends on @TimeZoneStorage and timezone.default_storage | behavioral | `OffsetTime` stored as `time` | `OffsetTime` stored as `time with time zone` on supported databases | Set `hibernate.timezone.default_storage=NORMALIZE` for backward compat | 6.2 — OffsetTime mapping changes |
| 6.2: UUID defaults to `uuid` type on MariaDB instead of `binary(16)` | behavioral | `UUID` stored as `binary(16)` on MariaDB | `UUID` stored as `uuid` on MariaDB | Set `hibernate.type.preferred_uuid_jdbc_type=BINARY` for backward compat | 6.2 — UUID mapping changes on MariaDB |
| 6.2: UUID defaults to `uniqueidentifier` on SQL Server instead of `binary(16)` | behavioral | `UUID` stored as `binary(16)` on SQL Server | `UUID` stored as `uniqueidentifier` on SQL Server | Set `hibernate.type.preferred_uuid_jdbc_type=BINARY` for backward compat | 6.2 — UUID mapping changes on SQL Server |
| 6.2: JSON defaults to `blob`/`json` on Oracle instead of `clob` | behavioral | `SqlTypes.JSON` stored as `clob` on Oracle | `SqlTypes.JSON` stored as `blob` (12.1+) or `json` (21+) on Oracle | Use `@Column(definition="clob")` for backward compat | 6.2 — JSON mapping changes on Oracle |
| 6.2: JSON defaults to `json` on H2 instead of `clob` | behavioral | `SqlTypes.JSON` stored as `clob` on H2 | `SqlTypes.JSON` stored as `json` on H2 1.4.200+ | Use `@Column(definition="clob")` for backward compat | 6.2 — JSON mapping changes on H2 |
| 6.2: Enum datatype now sensitive to entry count (>128 uses SMALLINT, <=128 uses TINYINT) | behavioral | All enums use SMALLINT (6.1) | Enums <=128 entries use TINYINT; >128 use SMALLINT | On MySQL, enums now use native ENUM datatype by default | 6.2 — Datatype for enums |
| 6.2: Timezone/offset storage default changed — may load incorrect dates if migrating from ORM 5 with non-UTC timezone | behavioral | `hibernate.timezone.default_storage=NORMALIZE` (normalize to jdbc.time_zone) | `hibernate.timezone.default_storage=DEFAULT` (store timezone if DB supports it) | Critical for OffsetDateTime/ZonedDateTime: existing data may load with wrong timezone; set to NORMALIZE for backward compat | 6.2 — Timezone and offset storage |
| 6.2: Byte[]/Character[] wrapper arrays disallowed by default | behavioral | `Byte[]`/`Character[]` mapped as `VARBINARY`/`VARCHAR` (treated as byte[]/char[]) | Default DISALLOW throws error; use `hibernate.type.wrapper_array_handling=legacy` or change to byte[]/char[] | Three options: change to primitives, set legacy mode, or set allow mode with schema migration | 6.2 — Byte[]/Character[] mapping changes |
| 6.2: UNIQUE constraint now generated for optional one-to-one mappings | behavioral | Optional `@OneToOne` on FK side had no UNIQUE constraint in DDL | UNIQUE constraint now correctly generated | May cause schema validation errors; remap as `@ManyToOne + @UniqueConstraint` if needed | 6.2 — UNIQUE constraint for optional one-to-one |
| 6.2: Query path comparisons are type-checked — incompatible types fail at query construction | behavioral | `where e.temporalAttribute > '2020-01-01'` (string compared with temporal) | `where e.temporalAttribute > date 2020-01-01` (proper temporal literal) | Entity vs literal comparisons also blocked; use entity.id for ID comparisons | 6.2 — Query Path comparison |
| 6.2: Batch fetching skipped when LockMode > READ | behavioral | Proxies batch-fetched regardless of lock mode | Proxies not batch-fetched when LockMode > READ (e.g., WRITE) | Only entity with specified lock mode is loaded; proxies remain uninitialized | 6.2 — Batch Fetching and LockMode |
| 6.2: Native queries with joins require table alias prefix for select * | structural | `SELECT * FROM person p LEFT JOIN dog d ON d.person_id = p.id` | `SELECT p.* FROM person p LEFT JOIN dog d ON d.person_id = p.id` | Same-named columns across joined tables cause errors; prefix with table alias | 6.2 — Native query with joins |
| 6.2: Legacy database version support removed — minimum versions enforced | removal | Older database versions supported via versioned dialect classes | Minimum versions: MySQL 5.7, PostgreSQL 10, Oracle 11.2, SQL Server 10.0, MariaDB 10.3, H2 1.4.197, DB2 10.5 | Legacy versions available via hibernate-community-dialects artifact | 6.2 — Removal of support for legacy database versions |
| 6.2: Check constraints now generated for boolean and enum mappings | behavioral | No check constraints generated for boolean/enum columns | Check constraints generated (e.g., `CHECK (col IN (0,1))` for boolean) | May cause schema validation differences | 6.2 — Check constraints for boolean and enum mappings |
| import.sql files must update sequence references from hibernate_sequence to per-entity sequences | structural | `insert into person (id, name) values (nextval('hibernate_sequence'), 'John');` | `insert into person (id, name) values (nextval('person_seq'), 'John'); alter sequence person_seq restart with 53;` | Must reset sequence values to account for allocation size | Implicit Identifier Sequence and Table Name |
