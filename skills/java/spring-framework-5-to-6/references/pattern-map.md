# Pattern Map — Spring Framework 5 to 6

| description | category | before | after | notes | source_section |
|---|---|---|---|---|---|
| Java 17 is now the minimum required version | addition | Java 8/11 JDK | Java 17+ JDK | Spring Framework 6.0 requires Java 17 or later | Baseline Upgrades (6.0) |
| Jakarta EE 9+ baseline; javax namespace migrated to jakarta | structural | `import javax.servlet.http.HttpServletRequest;` | `import jakarta.servlet.http.HttpServletRequest;` | Applies to Servlet, JPA, Validation, Inject, Annotation, etc. Spring still detects `javax` equivalents for pre-compiled binaries | Baseline Upgrades (6.0) |
| Servlet container must be upgraded to Jakarta EE 9+ versions | addition | Tomcat 9, Jetty 9/10, Undertow 2.x | Tomcat 10+, Jetty 11+, Undertow 2.2.19+ with `undertow-servlet-jakarta`; latest: Tomcat 10.1, Undertow 2.3 (Jakarta EE 10) | `javax.servlet` imports must change to `jakarta.servlet` | Web Applications (6.0) |
| Compile Java sources with -parameters flag instead of relying on -debug | structural | `javac -g` (relying on debug bytecode for parameter names) | Maven: `<plugin><artifactId>maven-compiler-plugin</artifactId><configuration><parameters>true</parameters></configuration></plugin>` / Gradle: `tasks.withType<JavaCompile>() { options.compilerArgs.add("-parameters") }` | `LocalVariableTableParameterNameDiscoverer` deprecated in 6.0, removed in 6.1; for Kotlin use `-java-parameters`; for Groovy use `-parameters` on GroovyCompile | Parameter Name Retention (6.1) |
| IDE must be configured for -parameters compilation | addition | | IntelliJ: Settings → Build, Execution, Deployment → Compiler → Java Compiler → Additional command line parameters: `-parameters`; Eclipse: Preferences → Java → Compiler → Store information about method parameters; VSCode: `.settings/org.eclipse.jdt.core.prefs` with `org.eclipse.jdt.core.compiler.codegen.methodParameters=generate` | Required for dependency injection, property binding, SpEL, Bean Validation parameter name resolution | Parameter Name Retention (6.1) |
| Bean property determination no longer uses java.beans.Introspector by default | behavioral | `org.springframework.beans.BeanInfoFactory=org.springframework.beans.ExtendedBeanInfoFactory` (in META-INF/spring.factories) | (no entry needed — SimpleBeanInfoFactory is default) | For full backwards compat with 5.3.x, add `ExtendedBeanInfoFactory`; for 5.3.x forward compat, use `SimpleBeanInfoFactory` | Core Container (6.0) |
| @Async methods must return Future or void | behavioral | `@Async public String process() { return "result"; }` | `@Async public CompletableFuture<String> process() { return CompletableFuture.completedFuture("result"); }` | Other return types now throw an exception; actively checked and enforced | Core Container (6.0) |
| SimpleEvaluationContext disables array allocations | behavioral | `context.setVariable("arr", new int[10]);` | (array allocation in SpEL no longer allowed in SimpleEvaluationContext) | Aligned with regular constructor resolution | Core Container (6.0) |
| JDBC exception translator changed to SQLExceptionSubclassTranslator | behavioral | Database-specific `SQLErrorCodeSQLExceptionTranslator` (default) | `SQLExceptionSubclassTranslator` detecting JDBC driver subclasses and SQL state; includes `DuplicateKeyException` check as of 6.0.3 | Re-enable legacy translator with user-provided `sql-error-codes.xml` or empty file in classpath root | Data Access and Transactions (6.0) |
| Hibernate ORM must be upgraded to 5.6.x (jakarta artifact) or 6.1 | addition | Hibernate ORM 5.x with `hibernate-core` | Hibernate ORM 5.6.x with `hibernate-core-jakarta` (Jakarta EE 9) or Hibernate ORM 6.1 (native `jakarta.persistence`) | Spring Boot 3.0 ships Hibernate 6.1; EclipseLink 3.0+ also supported | Data Access and Transactions (6.0) |
| Trailing slash matching default changed to false | behavioral | `@GetMapping("/some/greeting")` matches both `/some/greeting` and `/some/greeting/` | Only matches `/some/greeting`; `/some/greeting/` returns 404 | Restore old behavior: `configurer.setUseTrailingSlashMatch(true)` in `WebMvcConfigurer.configurePathMatch()`; or use explicit route: `@GetMapping("/some/greeting", "/some/greeting/")` | Web Applications (6.0) |
| Trailing slash handling via UrlHandlerFilter (6.2 replacement) | addition | `configurer.setUseTrailingSlashMatch(true)` (deprecated workaround) | Use `UrlHandlerFilter` (Servlet and reactive) to redirect or rewrite `/blog/blog-title/` to `/blog/blog-title` | UrlHandlerFilter is the proper replacement after `setUseTrailingSlashMatch` deprecation | Web Applications (6.2) |
| Controller detection requires @Controller annotation, not just @RequestMapping | behavioral | `@RequestMapping` on type level is sufficient for controller detection | Must annotate interface/class with `@Controller`; class-based proxying required for interface-based AOP proxying | Interface must also be annotated with `@Controller` if using interface-based AOP | Web Applications (6.0) |
| HttpMethod is now a class, not an enum | structural | `switch (method) { case GET: ... }` or `EnumSet<HttpMethod> methods` | `if (method == HttpMethod.GET) { ... }` or `Set<HttpMethod> methods = Set.of(HttpMethod.GET, HttpMethod.POST)` | Public API maintained but `switch` and `EnumSet` usage must be migrated | Web Applications (6.0) |
| RestTemplate requires Apache HttpClient 5 | structural | `HttpComponentsClientHttpRequestFactory` with HttpClient 4 | `HttpComponentsClientHttpRequestFactory` with HttpClient 5 (`org.apache.hc.client5`) | Package relocated from `org.apache.http` to `org.apache.hc` | Web Applications (6.0) |
| Servlet mocks require Servlet 6.0 API on test classpath | addition | `MockHttpServletRequest` with Servlet 5.0 API | `MockHttpServletRequest` needs Servlet 6.0 API jar on test classpath | Can still test Servlet 5.0 code and integrate with Servlet 5.0 containers; only mock-based tests need 6.0 API | Testing (6.0) |
| Observability instrumentation via Micrometer Observation is now built-in | addition | Manual metrics/tracing setup | `RestTemplate`, `WebClient`, Spring MVC (`ServerHttpObservationFilter`), Spring WebFlux instrumented out-of-box; `spring-web` requires `io.micrometer:micrometer-observation:1.10+` | Context Propagation integration for `Flux`/`Mono` controller returns | Observability (6.0) |
| PathPatternParser used by default in Spring MVC | behavioral | `AntPathMatcher` is default | `PathPatternParser` is default (can opt into `PathMatcher`) | May affect custom path matching logic or patterns relying on AntPathMatcher-specific behavior | Spring MVC (6.0) |
| ThreadPoolTaskExecutor/Scheduler enter graceful shutdown when context closes | behavioral | Executor accepts tasks until fully destroyed | Executor stops accepting tasks during stop/destroy callbacks | Set `acceptTasksAfterContextClose=true` to preserve old behavior at cost of longer shutdown | Core Container (6.1) |
| getMessage after context close throws IllegalStateException | behavioral | `context.getMessage(...)` works after close | `context.getMessage(...)` throws `IllegalStateException` after context close | Message resolution only allowed while context is active | Core Container (6.1) |
| Declarative caching detects reactive signatures for async caching | behavioral | `@Cacheable` caches the `Mono`/`Flux` Publisher instance | `@Cacheable` processes reactive methods for async caching of produced values | Requires cache provider support (e.g., `CaffeineCacheManager.setAsyncCacheMode(true)`); set `spring.cache.reactivestreams.ignore=true` to revert | Core Container (6.1) |
| @TransactionalEventListener rejects invalid @Transactional on same method | behavioral | `@TransactionalEventListener @Transactional` on same method (silently allowed) | Only `@Transactional(propagation = REQUIRES_NEW)` allowed on `@TransactionalEventListener` methods | Possibly combined with `@Async` | Data Access and Transactions (6.1) |
| JpaTransactionManager translates Hibernate exceptions to DataAccessException | behavioral | Hibernate transaction exception propagated as `JpaSystemException` | Translated to `DataAccessException` subclasses (e.g., `CannotAcquireLockException`); `JpaSystemException` for non-translatable fallback | `TransactionSystemException` from rollback now consistently `JpaSystemException` | Data Access and Transactions (6.1) |
| JDBC setNull bypasses getParameterType on PostgreSQL and SQL Server | behavioral | `getParameterType` resolution on all databases (extra DB roundtrip) | Bypassed on PostgreSQL and MS SQL Server by default for performance | Set `spring.jdbc.getParameterType.ignore=false` to restore; may affect null byte arrays | Data Access and Transactions (6.1) |
| Built-in method validation for controller parameters with @Constraint | structural | `@Validated` on controller class + AOP proxy for method validation | Remove `@Validated`; ensure `mvcValidator`/`webFluxValidator` is `jakarta.validation.Validator` (e.g., `LocalValidatorFactoryBean`); `MethodValidationException` raised instead of `ConstraintViolationException` | `@Valid` model attribute/request body validated at method level, not argument resolver level; `BindingResult` still respected | Web Applications (6.1) |
| Error message format changed for MethodArgumentNotValidException | behavioral | Errors joined with brackets and single quotes | Errors joined with `", and "` without quotes/brackets; field errors resolved through `MessageSource` | Applications have full control over error format by customizing individual error codes | Web Applications (6.1) |
| RouterFunctionMapping order changed from 3 to -1 | behavioral | `RouterFunctionMapping` ordered after `RequestMappingHandlerMapping` | `RouterFunctionMapping` ordered before `RequestMappingHandlerMapping` in both MVC and WebFlux | May affect request handling order if both router functions and annotated controllers match same path | Web Applications (6.1) |
| throwExceptionIfNoHandlerFound now true by default | behavioral | `DispatcherHandler.throwExceptionIfNoHandlerFound = false` | `true` by default (deprecated); `NoHandlerFoundException` / `NoResourceFoundException` handled as 404 with RFC 7807 responses | `ResourceHttpRequestHandler` raises `NoResourceFoundException` for missing static resources | Web Applications (6.1) |
| HTTP interface client removed 5-second default timeout | behavioral | 5-second default timeout on blocking HTTP interface methods | No default timeout; relies on underlying HTTP client configuration | Also applies to RSocket interface client | Web Applications (6.1) |
| ClientHttpRequestFactory no longer buffers request bodies | behavioral | Request bodies buffered; `Content-Length` header auto-set | Most implementations no longer buffer; `Content-Length` may not be set for JSON | Wrap in `BufferingClientHttpRequestFactory` to restore buffering | Web Applications (6.1) |
| Jackson ParameterNamesModule auto-registered by Jackson2ObjectMapperBuilder | behavioral | `ParameterNamesModule` not auto-registered | Auto-registered when on classpath; may change JSON serialization/deserialization behavior | Add `@JsonCreator` or `@JsonProperty("propertyName")` if needed; use `Jackson2ObjectMapperBuilder#modules` to disable auto-registration | Web Applications (6.1) |
| SpEL selector header disabled by default in WebSocket messaging | behavioral | SpEL-based `selector` header enabled in `DefaultSubscriptionRegistry` | Disabled by default; must explicitly enable | `registry.enableSimpleBroker().setSelectorHeaderName("selector");` in `WebSocketMessageBrokerConfigurer.configureMessageBroker()` | Messaging Applications (6.1) |
| AOT test processing now fails on error by default | behavioral | Errors during build-time AOT processing logged as warnings | Errors cause immediate build failure | Set `spring.test.aot.processing.failOnError=false` to continue after errors | Testing (6.1) |
| Revised autowiring: qualifier/parameter name overrule @Priority | behavioral | `@Priority` ranking checked before `@Qualifier` name match | `@Qualifier("...")` and parameter name matches overrule `@Priority` ranking | `@Primary` always comes first; `@Fallback` introduced in 6.2; mixing qualification mechanisms discouraged | Core Container (6.2) |
| Invalid @Configuration setups now rejected | behavioral | Invalid `@Configuration` classes silently accepted | Container rejects `@Bean void` return types and `@Bean @Autowired` combinations | Check for `@Bean` methods with void return or dual `@Bean @Autowired` annotations | Core Container (6.2) |
| Deeper generic type matching for autowiring | behavioral | Lenient generic type matching for injection | Stricter matching; injection points that previously matched by fallback may no longer match | Verify generic signatures at injection points and `@Bean` return types | Core Container (6.2) |
| @ComponentScan with REGISTER_BEAN condition fails hard | behavioral | `@ComponentScan` with late-evaluated conditions like `@ConditionalOnBean` | Framework fails if `@ComponentScan` uses a `REGISTER_BEAN` condition | Component scanning happens early in BeanFactory init; not suitable for late conditions | Core Container (6.2) |
| Bean definition overriding logged at INFO level | behavioral | Bean overriding silent by default | Each override logged at `INFO` level | Set `allowBeanDefinitionOverriding=true` on bean factory before refresh to silence | Core Container (6.2) |
| Property placeholder parser completely rewritten | structural | `${key:default}` where `:` is unescaped separator | Placeholder keys with `:` must be escaped: `${sub\://host}`; in properties files double the backslash: `my.host=${sub\\://host}`; placeholders can be escaped: `\${test}` → `${test}` | Constructs that worked by accident may break | Property Placeholder Resolution (6.2) |
| SpEL PropertyAccessor precedence changed | behavioral | Generic fallback accessors like `ReflectivePropertyAccessor` may take precedence | Type-specific `PropertyAccessor` implementations now properly take precedence over fallbacks | May need to revise `canRead()`/`canWrite()` implementations or registration order | SpEL (6.2) |
| RestClient.retrieve() no longer fire-and-forget | behavioral | `restClient.get().uri("/spring").retrieve();` fires HTTP request immediately | `restClient.get().uri("/spring").retrieve();` is a no-op; must invoke terminal operation | `ResponseEntity<Void> response = restClient.get().uri("/spring").retrieve().toBodilessEntity();` | HTTP Clients (6.2) |
| Static resource locations auto-appended with trailing slash | behavioral | String-based resource locations used as-is | Trailing slash appended automatically if not present | Path segment after last slash dropped by `Resource#createRelative`; does not affect `Resource`-configured locations | Web Applications (6.2) |
| WebFlux empty response bodies no longer write Content-Type header | behavioral | `Mono.empty()` response included Content-Type header | Content-Type header omitted for empty response bodies | Was invalid behavior per HTTP spec | Web Applications (6.2) |
| JMS DefaultMessageListenerContainer idleReceivesPerTaskLimit revised | behavioral | Core threads and surplus consumers both affected by idle timeout | Core threads always stay alive; only surplus consumers (between `concurrentConsumers` and `maxConcurrentConsumers`) time out | Only combined with `maxMessagesPerTask` does `idleReceivesPerTaskLimit` affect core consumers | Messaging Applications (6.2) |
| HtmlUnit test migration from 2.x to 3.x/4.x | structural | HtmlUnit 2.x APIs and Selenium driver `org.seleniumhq.selenium:htmlunit-driver` | HtmlUnit 4.2+ APIs and `org.seleniumhq.selenium:htmlunit3-driver:X.Y.Z` | See HtmlUnit migration guide at `htmlunit.sourceforge.io/migration.html` | Testing (6.2) |
| Jackson JMS converter trusted packages limited | addition | All packages trusted for deserialization by default | Use `setTrustedPackages(String... trustedPackages)` on `MappingJackson2MessageConverter` or `JacksonJsonMessageConverter` | Since 6.2.19; limits packages authorized for deserialization | Messaging Applications (6.2) |
| @Fallback beans introduced as companion to @Primary | addition | | `@Bean @Fallback MyService defaultMyService() { ... }` — used only if no other bean of same type provided | Inverse of `@Primary`: fallback bean is used when no other candidate exists | Core Container (6.2) |
| @TestBean, @MockitoBean, @MockitoSpyBean for bean overriding in tests | addition | | `@MockitoBean MyService mockService;` or `@MockitoSpyBean MyService spyService;` in test class | Framework-level support for bean overriding in tests; pairs with `@TestBean` | Testing (6.2) |
| RestClient introduced as synchronous HTTP client | addition | `RestTemplate` for synchronous HTTP | `RestClient` with API similar to `WebClient`; shares infrastructure with `RestTemplate` | Adapters for `RestClient`, `RestTemplate`, and `WebClient` in HTTP interface client | Web Applications (6.1) |
| UrlHandlerFilter for URL normalization (trailing slash redirect/rewrite) | addition | | `UrlHandlerFilter` (Servlet and reactive) to redirect `/blog/blog-title/` to `/blog/blog-title` | Proper replacement for deprecated `setUseTrailingSlashMatch` | Web Applications (6.2) |
