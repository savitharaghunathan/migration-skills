# Pattern Map — Spring Boot 2 to 3

| description | category | before | after | notes | source_section |
|---|---|---|---|---|---|
| Java 17 is now the minimum required version | addition | Java 8/11 JDK | Java 17+ JDK | Spring Boot 3.0 requires Java 17 or later; Java 8 is no longer supported | Review System Requirements |
| Upgrade to latest Spring Boot 2.7.x before migrating | addition | | Upgrade to latest 2.7.x maintenance release | Resolve all deprecation warnings on 2.7 before upgrading to 3.0 | Before You Start |
| Auto-configuration registration moved from spring.factories to imports file | structural | `META-INF/spring.factories` with `EnableAutoConfiguration` key | `META-INF/spring/org.springframework.boot.autoconfigure.AutoConfiguration.imports` | spring.factories key for EnableAutoConfiguration removed; other keys still work; libraries targeting both 2.x and 3.x can list in both files | Auto-configuration Files |
| Image banner support removed | removal | `banner.gif`, `banner.jpg`, `banner.png` in classpath root | Replace with text-based `banner.txt` | Image-based banners are now ignored | Image Banner Support Removed |
| Log date format changed to ISO-8601 | behavioral | `yyyy-MM-dd HH:mm:ss.SSS` | `yyyy-MM-dd'T'HH:mm:ss.SSSXXX` | Uses T separator and timezone offset; restore old format with `logging.pattern.dateformat` | Logging Date Format |
| Trailing slash URL matching deprecated and disabled | behavioral | `@GetMapping("/greeting")` matches both `/greeting` and `/greeting/` | Only matches `/greeting`; `/greeting/` returns 404 | Configure explicit redirect or declare both routes; can temporarily restore with `setUseTrailingSlashMatch(true)` | Spring MVC and WebFlux URL Matching Changes |
| Graceful shutdown SmartLifecycle phases changed | behavioral | Default phases for graceful shutdown | Shutdown begins at `SmartLifecycle.DEFAULT_PHASE - 2048`; web server stops at `DEFAULT_PHASE - 1024` | Update any custom SmartLifecycle implementations | Updated Phases for Graceful Shutdown |
| Jetty requires Servlet API downgrade for Spring Boot 3.0 | addition | Jetty with Servlet 5.0 | Downgrade Servlet API to 5.0 via `jakarta-servlet.version` property | Jetty does not yet support Servlet 6.0 in Spring Boot 3.0 | Jetty |
| JMX endpoint exposure default changed | behavioral | All endpoints exposed over JMX | Only health endpoint exposed over JMX by default | Configure with `management.endpoints.jmx.exposure.include` | JMX Endpoint Exposure |
| Actuator endpoints use isolated ObjectMapper | behavioral | Actuator uses application ObjectMapper | Actuator uses isolated ObjectMapper for consistent serialization | Set `management.endpoints.jackson.isolated-object-mapper=false` to revert; custom endpoints should implement OperationResponseBody | Actuator JSON |
| Actuator /env and /configprops mask all values by default | behavioral | Only keys matching sensitive patterns were masked | All values masked by default; role-based approach replaces key-based | Configure show-values property with NEVER/ALWAYS/WHEN_AUTHORIZED | Actuator Endpoints Sanitization |
| MongoDB HealthIndicator uses isMaster instead of buildInfo | behavioral | `buildInfo` query returning `version` field | `isMaster` query returning `maxWireVersion` (integer) field | Supports MongoDB Stable API; maxWireVersion is an integer, not a version string | Mongo Health Check |
| spring.data prefix now reserved for Spring Data | behavioral | `spring.data.*` properties used freely | `spring.data.*` implies Spring Data required on classpath | Cassandra moved out, Redis moved in | Changes to Data Properties |
| Observation-based metrics replace filter/interceptor-based instrumentation | structural | `WebMvcMetricsFilter`, `MetricsRestTemplateCustomizer`, tag providers | `ServerHttpObservationFilter`, `ObservationRestTemplateCustomizer`, observation conventions | Tag providers/contributors deprecated; extend DefaultServerRequestObservationConvention or implement convention interface | Micrometer and Metrics Changes |
| Micrometer JvmInfoMetrics auto-configured | addition | Manually define `JvmInfoMetrics` bean | Auto-configured; remove manual bean definition | | Auto-configuration of Micrometer's JvmInfoMetrics |
| Flyway FlywayConfigurationCustomizer called after Callback/JavaMigration beans added | behavioral | Customizer called before beans added | Customizer called after Callback and JavaMigration beans added | Applications defining both types and using a customizer may need updating | Flyway |
| Flyway cleanDisabled now defaults to true | behavioral | `flyway.cleanDisabled=false` (default) | `flyway.cleanDisabled=true` (default) | Must explicitly enable clean if needed | Flyway |
| @EnableBatchProcessing no longer required and now discouraged | structural | `@EnableBatchProcessing` on config class | Remove `@EnableBatchProcessing`; Spring Boot auto-configures Batch | Adding it causes auto-configuration to back off; define DefaultBatchConfiguration bean for full control | @EnableBatchProcessing |
| Multiple batch jobs no longer auto-run | behavioral | All detected jobs run on startup | Must specify single job with `spring.batch.job.name` | | Multiple Batch Jobs |
| Hibernate sequences per entity instead of single hibernate_sequence | structural | Single `hibernate_sequence` for all entities | Per-entity sequences: `<entity_name>_seq` | Use `hibernate.id.db_structure_naming_strategy=single` or `legacy` for backwards compatibility | Hibernate 6.0 Implicit Identifier Sequence |
| Hibernate sequence allocation size defaults to 50 | behavioral | Allocation size varied | Default allocation size 50 per JPA @SequenceGenerator spec | Existing data may need sequence reset: `alter sequence <name>_seq restart with <max_id + 1 + 50>` | Hibernate 6.0 Defaults for Implicit Sequence Generators |
| Hibernate BIGINT/count() now maps to Long instead of BigInteger | behavioral | `count()` returns `BigInteger` | `count()` returns `Long` | Native queries returning BIGINT affected | Hibernate 6.0 SQL BIGINT Mapping |
| Hibernate Duration maps to INTERVAL_SECOND instead of BIGINT | behavioral | Duration → `BIGINT` | Duration → `interval second` or `numeric(21)` | Set `hibernate.type.preferred_duration_jdbc_type=BIGINT` for compatibility; schema migration may be needed | Hibernate 6.0 Duration Mapping |
| Hibernate UUID maps to native uuid type instead of binary | behavioral | UUID → `binary(16)` | UUID → `uuid` native type (or `binary(16)` fallback) | Set `hibernate.type.preferred_uuid_jdbc_type=BINARY` for compatibility | Hibernate 6.0 UUID Mapping |
| Hibernate Instant maps to TIMESTAMP_UTC instead of TIMESTAMP | behavioral | Instant → `timestamp` | Instant → `timestamp with time zone` | Set `hibernate.type.preferred_instant_jdbc_type=TIMESTAMP` for compatibility | Hibernate 6.0 Instant Mapping |
| Hibernate query result rows changed for implicit select with joins | behavioral | `from Person p join p.address` returns `List<Object[]>` | Returns `List<Person>` | Use `select p, a from Person p join p.address a` to get Object[] | Hibernate 6.0 Query Result Rows |
| Hibernate DISTINCT no longer needed to filter parent duplicates in join fetch | behavioral | `select distinct p from Person p join fetch p.addresses` needed | Remove `distinct`; Hibernate 6.0 auto-filters duplicates | `QueryHints.HINT_PASS_DISTINCT_THROUGH` removed | Hibernate 6.0 DISTINCT |
| Hibernate ordinal parameter binding is now 1-based | behavioral | `?0` with `setParameter(0, ...)` | `?1` with `setParameter(1, ...)` | 0-based positional binding no longer supported | Hibernate 6.0 Ordinal Parameters |
| Hibernate association comparison requires FK dereference | behavioral | `where alias.association = 1` | `where alias.association.id = 1` | Direct FK value comparison no longer allowed; use entity reference or dereference .id | Hibernate 6.0 Association Comparisons |
| Hibernate collection pseudo-attributes replaced by functions | structural | `p.addresses.size`, `p.addresses.elements` | `size(p.addresses)`, `value(p.addresses)` | Also: `index()`, `key()`, `maxindex()`, `minindex()`, `maxelement()`, `minelement()` | Hibernate 6.0 Collection Pseudo-attributes |
| Hibernate hbm.xml mappings deprecated | removal | `hbm.xml` mapping files | Use JPA annotations or `orm.xml` | Will not be supported beyond 6.x | Hibernate 6.0 Deprecation of hbm.xml |
| Hibernate lazy associations with fetch=join now respected | behavioral | `@ManyToOne(fetch=LAZY)` with `@Fetch(JOIN)` treated as eager for by-id load | Laziness properly respected for all load mechanisms | Set `fetch=EAGER` explicitly if eager loading needed | Hibernate 6.0 Association Laziness |
| Hibernate NativeQuery no longer supports callable procedures | structural | `@NamedNativeQuery(callable = true)` | Use `@NamedStoredProcedureQuery` or `ProcedureCall` / `StoredProcedureQuery` | Temporary auto-translation in 6.0; will be removed in future versions | Hibernate 6.0 Callable via NativeQuery |
| Hibernate Interceptor.onSave id parameter changed from Serializable to Object | structural | `boolean onSave(Object entity, Serializable id, ...)` | `boolean onSave(Object entity, Object id, ...)` | Always use @Override to catch this change | Hibernate 6.0 Interceptor |
| Hibernate Stream no longer auto-closes resources | behavioral | Stream from query auto-managed | Must explicitly call `Stream.close()` to avoid resource leaks | Use try-with-resources | Hibernate 6.0 Stream |
| Hibernate Enum mapping changed from TINYINT to SMALLINT | behavioral | Enum → `TINYINT` | Enum → `SMALLINT` | Schema validation handles mismatch; migration: `alter column enum_col smallint` | Hibernate 6.1 Enum Mapping |
| Hibernate basic array/collection mapping changed to SQL ARRAY | behavioral | Arrays serialized via `VARBINARY` | Arrays use `SqlTypes.ARRAY` (native SQL array) or JSON/XML fallback | Use `@JdbcTypeCode(SqlTypes.VARBINARY)` for compatibility; data migration required | Hibernate 6.1 Basic Array Mapping |
| Spring Security applies authorization to all dispatch types | behavioral | Only REQUEST dispatch type authorized | FORWARD, INCLUDE, and other dispatch types also secured | Configurable via `spring.security.filter.dispatcher-types` | Spring Security Dispatch Types |
| @Configuration required on @EnableWebSecurity classes | structural | `@EnableWebSecurity` included `@Configuration` | Must add `@Configuration` explicitly alongside `@EnableWebSecurity` | Also applies to @EnableMethodSecurity, @EnableGlobalMethodSecurity, @EnableGlobalAuthentication | Spring Security @Configuration |
| SecurityContext no longer auto-persisted between requests | behavioral | `SecurityContextPersistenceFilter` auto-saved context | Must explicitly save SecurityContext via SecurityContextRepository | `SecurityContextHolderFilter` only reads, does not save | Spring Security SecurityContext Persistence |
| RequestCache only checked when HTTP parameter 'continue' present | behavioral | RequestCache queried on every request | Only queried when `continue` parameter present | Avoids unnecessary HttpSession reads | Spring Security RequestCache |
| CSRF token loading changed to deferred by default | behavioral | CSRF token loaded on every request | `csrfRequestAttributeName` defaults to `_csrf`; token loaded lazily | | Spring Security CSRF Token |
| Gradle bootJar main class resolution simplified | structural | Main class resolved from various sources | Resolved from main source set output only | Configure via `springBoot { mainClass = "..." }` or `resolveMainClassName` task | Gradle Main Class Resolution |
| Gradle task properties use Property API | structural | `isEnabled = false` | `enabled.set(false)` | Kotlin DSL may need changes for property setting | Configuring Gradle Tasks |
| Gradle build-info exclusion mechanism changed | structural | Set properties to null to exclude | Use name-based exclusion: `excludes = ['time']` | | Excluding Properties From build-info.properties |
| Maven spring-boot:run fork attribute removed | removal | `<fork>true</fork>` in plugin config | Remove fork attribute; always forks by default | Deprecated since Spring Boot 2.7 | Maven Running Your Application |
| Hibernate configuration property renames (ejb prefix removed) | structural | `hibernate.ejb.metamodel.population` | `hibernate.jpa.metamodel.population` | Multiple properties: ejb.cfgfile → cfg_xml_file, ejb.xml_files → orm_xml_files, etc. | Hibernate 6.0 Configuration Property Renames |
| Hibernate multitenancy simplified — no explicit config needed | structural | `hibernate.multiTenancy` property required | Remove property; auto-detected from MultiTenantConnectionProvider or @TenantId | MultiTenancyStrategy enum removed | Hibernate 6.0 Multitenancy |
| Hibernate community dialects moved to separate module | addition | Community dialects in hibernate-core | Add `org.hibernate.orm:hibernate-community-dialects` dependency | Required for CacheDialect, CUBRIDDialect, FirebirdDialect, etc. | Hibernate 6.0 Community Dialects |
| Hibernate CompositeUserType reworked with embeddable projection | structural | `CompositeUserType` with propertyNames/propertyTypes methods | Return embeddable projection class; use `@AttributeOverride` instead of `@Columns` | Property index is 0-based, sorted lexicographically by attribute name | Hibernate 6.0 CompositeUserType |
| Hibernate pass-through tokens in HQL no longer allowed | behavioral | `substring(e.desc, 21, 11, octets)` | `substring(e.desc, 21, 11, sql('octets'))` | Use `sql()` function for pass-through SQL tokens | Hibernate 6.0 Pass-through Tokens |
| Hibernate UPDATE statements no longer allow FROM keyword | behavioral | `update from MyEntity e set ...` | `update MyEntity e set ...` | Remove optional FROM keyword | Hibernate 6.0 FROM Token |
| Hibernate bulk_id_strategy config renamed | structural | `hibernate.hql.bulk_id_strategy` | `hibernate.query.mutation_strategy` | Now references SqmMultiTableMutationStrategy implementations | Hibernate 6.0 Multi-table Mutation |
| Flyway MigrationType enum replaced with CoreMigrationType | structural | `MigrationType.SQL` | `CoreMigrationType.SQL` | SQL_BASELINE and JDBC_BASELINE types moved to flyway-proprietary | Flyway |
| Flyway undo command requires flyway-proprietary module | addition | Undo in flyway-core | Add `flyway-proprietary` to classpath for undo; extend `UndoJavaMigration` instead of `BaseJavaMigration` | | Flyway |
| Password encoder minimums updated for PBKDF2, SCrypt, Argon2 | behavioral | Previous default iterations/parameters | Updated minimums; use static factory methods referencing Spring Security version | e.g., `Pbkdf2PasswordEncoder.defaultsForSpringSecurity_v5_8()` | Spring Security Password Encoding |
